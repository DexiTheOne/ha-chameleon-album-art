# Chameleon change log

## 2026-09-23 — Random scene color assignment

- Request: provide a toggle that changes the light-to-palette order each time Random chooses an image.
- Implementation: added Randomize Color Assignment to the Chameleon setup and Configure options. When enabled, a Random invocation chooses an image and shuffles a copy of the configured light list. The shuffled list controls static palette assignment and animated starting-color order. A repeated Random invocation avoids reusing the previous order when more than one light is available. Named scenes and Album Art use the configured order. The chosen assignment survives transition or style reapplication of the active scene.
- Validation: 50 local tests passed, including unchanged configured light order, shuffled assignments, repeat selection, and single-light behavior. HACS installed commit `8125e7b` on Home Assistant Core 2026.8.3. The existing entry retained its album-art source, Normalize Brightness option, seven controlled-light IDs, and transition-style setting. The Randomize Color Assignment option was enabled and read back as `true`. Two live Random selections chose different images and produced different seven-light assignment orders with all seven members present. Applying named scene Aquatic returned to the configured order. No Chameleon error appeared in the log.
- Test cleanup: the temporary scene did not turn three previously off lights back off. Those three lights were turned off individually after the Chameleon transition was returned to its pre-update value of 0 seconds. Final readback matched the pretest on/off states for all seven lights; Chameleon was on Aquatic with no animation, as before the deployment restart. For future tests, verify each light after scene restoration and correct any missed off states directly.
- Recovery: disable the toggle in Configure to return Random to the configured order. No entity IDs, unique IDs, or controlled-light configuration are changed.

## 2026-09-23 — RGB normalization and output bounds

- Request: add a Normalize Brightness toggle that changes extracted color values for brighter, more vibrant LED palettes while leaving the Home Assistant brightness setting alone; ensure every RGB service call stays within standard channel bounds.
- Implementation: added the toggle to new-entry setup and the existing entry's Configure options. When enabled, image and album-art palette colors retain their hue, reach maximum HSV value, and receive a minimum saturation for chromatic colors. Neutral colors become white. Animated gradient steps receive the same treatment. Manual color selection keeps its requested color. Static, animated, and manual light commands now clamp every RGB channel to an integer from 0 to 255 immediately before the service call. The default is off for existing entries.
- Validation: 46 local tests passed, including dark/muted/neutral palette, animated gradient, and out-of-range RGB cases; Python compilation, JSON validation, and whitespace checks passed. HACS installed commit `c06864a` on Home Assistant Core 2026.8.3. After restart the original integration entry and seven controlled light IDs remained loaded. The live `normalize_brightness` option was enabled and read back as `true`; the transition stayed at 5 seconds and the style stayed staggered. A brief static Aquatic scene test produced seven bounded RGB triples, each with a maximum channel value of 255. The temporary scene restored the controlled lights, Chameleon returned to off, and the transition was reset to 5 seconds. No Chameleon error appeared in the log.
- Limits: equal RGB maximum values do not ensure equal perceived brightness across different hues or LED hardware. Exact physical matching requires device calibration. Home Assistant's separate brightness control remains unchanged.
- Recovery: disable Normalize Brightness in the Chameleon Configure dialog to restore original extracted colors; reinstall the prior HACS commit if needed. The previous session found that Home Assistant cannot create a full backup until a default backup password is configured.
